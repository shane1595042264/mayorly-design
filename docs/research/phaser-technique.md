# Phaser pixel-perfect technique for todoFarm (research, September 2026)

## Bottom line

**1. Use Phaser 4, specifically `phaser@4.2.1`.** Phaser 4.0.0 shipped stable on 2026-04-10 and 4.2.1 on 2026-07-09; Phaser 3's last release was 3.90.0 on 2025-05-23, over a year earlier. Phaser 4 is MIT licensed (safe for a closed-source commercial `.app`). Evidence: [npm registry dist-tags](https://registry.npmjs.org/phaser) show `latest: 4.2.1`; [GitHub releases](https://github.com/phaserjs/phaser/releases) list v4.2.1 (2026-07-09) as the newest non-prerelease and v3.90.0 (2025-05-23) as the last v3; [LICENSE.md](https://github.com/phaserjs/phaser/blob/v4.2.1/LICENSE.md) is MIT, "Copyright (c) 2026 Richard Davey, Phaser Studio Inc."; [phaser.io/download/stable](https://phaser.io/download/stable) offers "Phaser v4.2.1 Giedi".

**2. Get crispness from `pixelArt: true` plus `scale.zoom`, and keep `camera.zoom` at 1.** This is the single most consequential finding. In Phaser 4, per-object vertex rounding defaults to `'safeAuto'`, and "safe" is decided by a check that the composed matrix has **unit scale** ([`TransformerImage.js#L182`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/renderer/webgl/renderNodes/transformer/TransformerImage.js#L182)). A camera at `zoom: 3` makes that check false, so the default rounding silently stops applying to every sprite and tile. Zooming via `scale.zoom` scales the canvas in CSS instead, leaving the camera at zoom 1 and rounding intact.

**3. Ship a small canvas (roughly 480x270) scaled up by an integer, not a big canvas with a zoomed camera.**

**4. For the HTML UI: use a plain absolutely-positioned overlay div, NOT Phaser's `DOMElement`.** Two source-level disqualifiers for `DOMElement` in a text-heavy app: Phaser applies `transform: scale(...)` to its DOM container to match the canvas zoom ([`ScaleManager.js#L987`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/ScaleManager.js#L987)), which would blow your chat text up 3x and blur it; and DOM Elements "cannot be blended into the display list" and "cannot be enabled for input" ([official docs](https://docs.phaser.io/phaser/concepts/gameobjects/dom-element)). Phaser Studio's own React/Vue/Svelte templates, updated for Phaser 4, put the UI in sibling DOM and bridge with an event bus, not `DOMElement` ([template-react README](https://github.com/phaserjs/template-react/blob/main/README.md)).

**5. The keyboard handoff is a real bug you must write code for, and it has a one-line fix.** Phaser's KeyboardManager attaches to `window` by default ([`Config.js#L226`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L226), [`KeyboardManager.js#L164`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardManager.js#L164)), while the MouseManager attaches to the canvas ([`MouseManager.js#L254`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/mouse/MouseManager.js#L254)). Keydowns inside your HTML `<input>` bubble to `window` and Phaser queues them with no filtering on `event.target`, so typing "walk the dog" makes your character walk. Fix: toggle `this.input.keyboard.enabled = false` plus `resetKeys()` when the overlay takes focus.

## 1. Exact config for crisp pixel-perfect rendering at integer zoom

### What `pixelArt: true` actually does

Verified in source at [`Config.js#L395-L405`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L395-L405):

```js
this.pixelArt = GetValue(renderConfig, 'pixelArt', false, config);
if (this.pixelArt)
{
    this.antialias = false;
    this.antialiasGL = false;
    this.roundPixels = true;
}
```

Downstream consequences, each confirmed in source:

1. **Texture filtering becomes NEAREST.** LINEAR filtering is applied only when `this.config.antialias` is true ([`WebGLRenderer.js#L1704`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/renderer/webgl/WebGLRenderer.js#L1704) and [#L2322](https://github.com/phaserjs/phaser/blob/v4.2.1/src/renderer/webgl/WebGLRenderer.js#L2322)); otherwise the filters stay NEAREST.
2. **The canvas element gets `image-rendering: pixelated`.** [`CreateRenderer.js#L92-L95`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/CreateRenderer.js#L92-L95) calls `CanvasInterpolation.setCrisp(game.canvas)` whenever `!config.antialias`. `setCrisp` writes a vendor-prefixed ladder ending in `pixelated` ([`CanvasInterpolation.js`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/display/canvas/CanvasInterpolation.js)). This is what makes the CSS upscale crisp.
3. **Cameras inherit `roundPixels: true`.** `CameraManager.roundPixels = scene.sys.game.config.roundPixels`, and the default main camera is created through `add()`, which calls `camera.setRoundPixels(this.roundPixels)` ([`CameraManager.js#L87`, `#L247`, boot at `#L~330`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/cameras/2d/CameraManager.js)).

Note `roundPixels` now **defaults to `false`** in v4 (it was `true` in v3): [`Config.js#L382`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L382), and the [migration guide section 16](https://github.com/phaserjs/phaser/blob/master/changelog/v4/4.0/MIGRATION-GUIDE.md) confirms. `pixelArt: true` is what turns it back on.

### The v4 rounding model, and why camera zoom breaks it

New in v4: every Game Object has `vertexRoundMode`, defaulting to `'safeAuto'` ([`GameObject.js#L222`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/GameObject.js#L222)):

```js
willRoundVertices: function (camera, onlyTranslated)
{
    switch (this.vertexRoundMode)
    {
        case 'safe':     return onlyTranslated;
        case 'safeAuto': return onlyTranslated && camera.roundPixels;
        case 'full':     return true;
        case 'fullAuto': return camera.roundPixels;
        case 'off':
        default:         return false;
    }
}
```
([`GameObject.js#L728-L750`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/GameObject.js#L728))

And `onlyTranslated` is computed as a strict unit-scale test on the fully composed matrix ([`TransformerImage.js#L178-L196`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/renderer/webgl/renderNodes/transformer/TransformerImage.js#L178)):

```js
var cmm = calcMatrix.matrix;
var onlyTranslate = cmm[0] === 1 && cmm[1] === 0 && cmm[2] === 0 && cmm[3] === 1;

if (gameObject.willRoundVertices(camera, onlyTranslate))
{
    // Math.round() all 8 quad components
}
```

`calcMatrix` starts from `camera.getViewMatrix(...)`, which is built with `matrix.applyITRS(originX, originY, this.rotation, zoomX, zoomY)` ([`Camera.js` preRender](https://github.com/phaserjs/phaser/blob/v4.2.1/src/cameras/2d/Camera.js#L535)). So at `camera.setZoom(3)`, `cmm[0] === 3`, `onlyTranslate` is false, and with the default `safeAuto` **nothing gets rounded**. The same code path exists for tiles ([`TransformerTile.js#L145`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/renderer/webgl/renderNodes/transformer/TransformerTile.js#L145)), so tile seams reappear too.

There is a second corroborating signal: `Camera.preRender` sets `renderRoundPixels = (this.roundPixels && Number.isInteger(zoomX) && Number.isInteger(zoomY))` ([`Camera.js#L535`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/cameras/2d/Camera.js#L535)). Phaser itself treats non-integer camera zoom as incompatible with rounding.

### Recommended config for todoFarm

```js
import Phaser from 'phaser';

const BASE_W = 480;   // 30 tiles at 16px
const BASE_H = 270;   // 16.875 tiles; 16:9, scales cleanly to 1920x1080

export default new Phaser.Game({
    type: Phaser.AUTO,          // AUTO falls back to Canvas; Phaser.WEBGL does not
    parent: 'game-container',
    width: BASE_W,
    height: BASE_H,
    pixelArt: true,             // -> antialias:false, antialiasGL:false, roundPixels:true
    backgroundColor: '#1b1b1b',
    scale: {
        mode: Phaser.Scale.NONE,          // we control size ourselves
        autoCenter: Phaser.Scale.CENTER_BOTH,
        zoom: Phaser.Scale.MAX_ZOOM       // largest integer multiple that fits the parent
    },
    dom: { createContainer: false },      // we are NOT using Phaser DOMElements
    physics: {
        default: 'arcade',
        arcade: { gravity: { y: 0 }, debug: false }
    },
    scene: [ Boot, Preload, Farm ]
});
```

Then, because `MAX_ZOOM` is resolved **once at boot** and never recomputed (`parseConfig` at [`ScaleManager.js#L556-L559`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/ScaleManager.js#L556) resolves the constant into a number; nothing re-resolves it on resize), you must re-apply it yourself when the Tauri window resizes:

```js
// once, after `new Phaser.Game(...)`
window.addEventListener('resize', () => game.scale.setMaxZoom());
```

`setMaxZoom()` and `getMaxZoom()` are real public methods ([`ScaleManager.js#L1184`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/ScaleManager.js#L1184)); `getMaxZoom` uses `SnapFloor` on parent size divided by game size and clamps to a minimum of 1, so it always yields a whole number.

**Zoom constants** ([`ZOOM_CONST.js`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/const/ZOOM_CONST.js), summarized in the official [scale skill](https://github.com/phaserjs/phaser/blob/master/skills/scale-and-responsive/SKILL.md)): `NO_ZOOM: 1`, `ZOOM_2X: 2`, `ZOOM_4X: 4`, `MAX_ZOOM: -1`. Any numeric value is accepted. "The zoom affects CSS display size but not the canvas resolution", which is exactly what you want.

**Scale modes** ([`SCALE_MODE_CONST.js`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/const/SCALE_MODE_CONST.js)): `NONE: 0`, `WIDTH_CONTROLS_HEIGHT: 1`, `HEIGHT_CONTROLS_WIDTH: 2`, `FIT: 3`, `ENVELOP: 4`, `RESIZE: 5`, `EXPAND: 6` (EXPAND is new in v4).

Do **not** use `FIT` for pixel art unless you also snap: `FIT` produces fractional CSS scale factors and you will get uneven pixel widths. If you want FIT-like letterboxing, `NONE + autoCenter + MAX_ZOOM` gets you an integer scale with black bars, which is the Stardew look.

### The two remaining crispness leaks

- **Fractional camera scroll.** Even with rounding on, a camera following the player with lerp will sit at `scrollX = 103.47`. Because rounding happens on the quad after the view matrix, sprite edges land on whole game pixels, but the tilemap will still shimmer at some scroll values. The blunt fix is to floor the scroll in a `postupdate` hook. I did **not** find an official Phaser 4 example doing this, so treat it as a technique to test rather than a documented recipe:

  ```js
  this.events.on(Phaser.Scenes.Events.POST_UPDATE, () => {
      const cam = this.cameras.main;
      cam.scrollX = Math.round(cam.scrollX);
      cam.scrollY = Math.round(cam.scrollY);
  });
  ```

- **Tileset bleeding.** Adjacent tiles sampling a neighbour's edge texel. The standard fix is extruding the tileset by 1px, using [`tile-extruder`](https://github.com/sporadic-labs/tile-extruder) (npm `tile-extruder@2.1.1`, last published 2025-01-28), whose description links the [original Phaser issue #3229](https://github.com/photonstorm/phaser/issues/3229). Phaser 4's `TilemapGPULayer` claims to solve this natively: "Smooth tile borders with LINEAR filtering (no seams)" ([tilemaps skill](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md)).

### If you ever DO need camera zoom

For a "zoom in on the chest" cinematic, camera zoom is the right tool, but set the affected objects to full rounding so they do not go blurry-adjacent:

```js
player.setVertexRoundMode('fullAuto');   // rounds whenever camera.roundPixels is true
groundLayer.setVertexRoundMode('fullAuto');
```
(`setVertexRoundMode` at [`GameObject.js#L762`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/GameObject.js#L762).) Note this rounds in **screen** space, so at integer camera zoom the pixel grid stays even, but sprites snap in sub-game-pixel increments. **I could not verify this visually**; it is derived from reading the transformer code.

## 2. Loading a Tiled tilemap and rendering layers

### File format reality check

- **`.tmj` works, `.tmx` does not.** There is no TMX (XML) parser anywhere in the source: `src/tilemaps/parsers/` contains only `tiled/` (JSON), `impact/`, `ParseCSV.js` and `Parse2DArray.js` ([directory listing](https://github.com/phaserjs/phaser/tree/v4.2.1/src/tilemaps/parsers)). Export from Tiled as JSON.
- The loader only auto-appends `.json` when you omit the URL: "If the URL isn't specified the Loader will take the key and create a filename from that... It will always add `.json` as the extension... If you do not desire this action then provide a URL" ([`TilemapJSONFile.js#L113-L116`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/loader/filetypes/TilemapJSONFile.js)). So `this.load.tilemapTiledJSON('farm', 'maps/farm.tmj')` is fine.
- **Infinite (chunked) maps are supported**: "Both finite and infinite (chunked) Tiled maps are handled" ([`ParseTileLayers.js#L26`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/tilemaps/parsers/tiled/ParseTileLayers.js#L26)).
- **"Collection of Images" tilesets are NOT supported.** "The Phaser Tiled parser does not support 'Collection of Images' tilesets. All tiles must be in a single tileset image per tileset." ([tilemaps skill](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md)). This matters for todoFarm: if you want chests as tileset objects, put them all in one sheet, or place them as object-layer entries instead.

### Code

```js
preload ()
{
    this.load.tilemapTiledJSON('farm', 'maps/farm.tmj');
    this.load.image('farm-tiles', 'maps/farm-tileset-extruded.png');
    this.load.spritesheet('player', 'sprites/player.png', { frameWidth: 16, frameHeight: 32 });
}

create ()
{
    const map = this.add.tilemap('farm');

    // 1st arg = tileset NAME as it appears in Tiled, 2nd = Phaser texture key
    const tiles = map.addTilesetImage('farm-tileset', 'farm-tiles');

    // createLayer(layerID, tileset, x, y, gpu)
    const ground   = map.createLayer('Ground', tiles, 0, 0);
    const props    = map.createLayer('Props', tiles, 0, 0);
    const canopy   = map.createLayer('Canopy', tiles, 0, 0);

    props.setCollisionByProperty({ collides: true });   // property set in Tiled's tileset editor

    ground.setDepth(-10);
    props.setDepth(-5);      // props BELOW the y-sorted band; see section 4
    canopy.setDepth(10000);  // treetops always above the player

    this.cameras.main.setBounds(0, 0, map.widthInPixels, map.heightInPixels);
    this.physics.world.setBounds(0, 0, map.widthInPixels, map.heightInPixels);
}
```

`createLayer(layerID, tileset, x, y, gpu)` signature and the whole flow are documented in the [official tilemaps skill](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md); a live example is [`tilemap/collision/csv map arcade physics.js`](https://github.com/phaserjs/examples/blob/master/public/src/tilemap/collision/csv%20map%20arcade%20physics.js).

### GPU layer, worth it for todoFarm?

Pass `true` as the 5th arg to `createLayer` to get a `TilemapGPULayer`. Constraints from the [tilemaps skill](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md): single tileset per layer, orthographic only, WebGL only, max 4096x4096 tiles, and **layer edits do not display until you call `generateLayerDataTexture()`**.

For a small farm the CPU `TilemapLayer` is plenty and gives you multi-tileset support. **Recommendation: start with the CPU layer.** Reach for the GPU layer only if you hit seams you cannot fix by extruding, since its "no seams" property is the one real draw here.

### Tilemap gotchas that will bite you

Directly from the [official skill's Gotchas section](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md):

1. Tileset name must match Tiled exactly, or `addTilesetImage` returns `null` with a console warning.
2. Layer name must match Tiled exactly. Tiled group layers are flattened to `'GroupName/LayerName'`.
3. Each layer can only be created once; a second `createLayer` on the same ID returns `null`.
4. `setCollision*` must be called before `physics.add.collider` does anything.
5. If you omit `x`/`y` in `createLayer`, it defaults to the **layer offset defined in Tiled**, not (0, 0).
6. Tile index `-1` means empty; most getters return `null` unless you pass `nonNull: true`.

## 3. Four-direction character controller with walk animation and tile collision

This is the canonical official example, [`tilemap/collision/csv map arcade physics.js`](https://github.com/phaserjs/examples/blob/master/public/src/tilemap/collision/csv%20map%20arcade%20physics.js), adapted to a Tiled JSON map and normalized diagonal speed:

```js
const SPEED = 60;   // game px/sec at 16px tiles feels about right

create ()
{
    // ... map setup from section 2 ...

    for (const [ key, row ] of Object.entries({ down: 0, left: 1, right: 2, up: 3 }))
    {
        this.anims.create({
            key: `walk-${key}`,
            frames: this.anims.generateFrameNumbers('player', { start: row * 4, end: row * 4 + 3 }),
            frameRate: 8,
            repeat: -1
        });
        this.anims.create({
            key: `idle-${key}`,
            frames: this.anims.generateFrameNumbers('player', { frames: [ row * 4 ] }),
            frameRate: 1
        });
    }

    this.player = this.physics.add.sprite(120, 120, 'player', 0);
    this.player.setOrigin(0.5, 1);                 // feet at y, makes Y-sorting correct
    this.player.body.setSize(12, 8);               // small feet-box, not the whole sprite
    this.player.body.setOffset(2, 24);             // push the box down to the feet
    this.player.body.setCollideWorldBounds(true);

    this.physics.add.collider(this.player, props);

    this.cursors = this.input.keyboard.createCursorKeys();
    this.wasd    = this.input.keyboard.addKeys('W,A,S,D');
    this.facing  = 'down';

    this.cameras.main.startFollow(this.player, true, 0.15, 0.15);
}

update ()
{
    const b = this.player.body;
    b.setVelocity(0);

    const left  = this.cursors.left.isDown  || this.wasd.A.isDown;
    const right = this.cursors.right.isDown || this.wasd.D.isDown;
    const up    = this.cursors.up.isDown    || this.wasd.W.isDown;
    const down  = this.cursors.down.isDown  || this.wasd.S.isDown;

    if (left)  { b.setVelocityX(-SPEED); this.facing = 'left'; }
    else if (right) { b.setVelocityX(SPEED); this.facing = 'right'; }
    if (up)    { b.setVelocityY(-SPEED); this.facing = 'up'; }
    else if (down) { b.setVelocityY(SPEED); this.facing = 'down'; }

    // left/right animation wins over up/down, matching the official example
    if (left || right) this.facing = left ? 'left' : 'right';

    b.velocity.normalize().scale(SPEED);   // stops diagonals being 1.41x faster

    const moving = left || right || up || down;
    this.player.anims.play(`${moving ? 'walk' : 'idle'}-${this.facing}`, true);
}
```

Notes with sources:

- `createCursorKeys()` returns `{ up, down, left, right, space, shift }` ([input skill](https://github.com/phaserjs/phaser/blob/master/skills/input-keyboard-mouse-touch/SKILL.md)).
- `generateFrameNumbers(key, { start, end })` or `{ frames: [...] }` ([animations skill](https://github.com/phaserjs/phaser/blob/master/skills/animations/SKILL.md)).
- `body.setSize(w, h, center)` and `body.setOffset(x, y)` ([arcade physics skill](https://github.com/phaserjs/phaser/blob/master/skills/physics-arcade/SKILL.md)). A feet-only hitbox is what makes a top-down character feel Stardew-like: you can walk "behind" a fence with your head overlapping it.
- Collision by Tiled property: `layer.setCollisionByProperty({ collides: true })`, and it accepts arrays (`{ type: ['wall', 'water'] }`). Alternatives: `setCollision([indexes])`, `setCollisionBetween(a, b)`, `setCollisionByExclusion([-1, 0])`, `setCollisionFromCollisionGroup()` ([tilemaps skill](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md)).
- Debug the collision boxes with `map.renderDebug(graphics, { collidingTileColor, faceColor })`, exactly as the official example does.

**Alternative worth considering: grid-locked movement.** Stardew is free-movement, but a tile-locked mover eliminates the fractional-position problem entirely. The official example is [`tilemap/grid movement.js`](https://github.com/phaserjs/examples/blob/master/public/src/tilemap/grid%20movement.js). I did not read it in full, so I am flagging it as a lead rather than a verified recipe.

## 4. Y-sorted depth

Phaser's display list sorts by `depth` on every render, and setting `depth` on any object queues that sort:

- `Depth` setter calls `this.displayList.queueDepthSort()` ([`Depth.js#L52-L60`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/components/Depth.js#L52)).
- `Systems.render` calls `displayList.depthSort()` before rendering ([`Systems.js#L378`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scene/Systems.js#L378)).
- `depthSort` uses `StableSort` on the depth comparator ([`DisplayList.js#L185-L193`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/DisplayList.js#L185)).

So the whole technique is: **set `depth = y` every frame on anything that can be walked around**. This is precisely what the official [`depth sorting/isometric blocks.js`](https://github.com/phaserjs/examples/blob/master/public/src/depth%20sorting/isometric%20blocks.js) example does: `tile.setDepth(centerY + ty);`.

Cleanest structure for todoFarm, using a `Layer` so only your sortable band re-sorts:

```js
create ()
{
    // ground/props/canopy tilemap layers get fixed depths (section 2)

    this.ySort = this.add.layer();       // its own display list with its own sort
    this.ySort.setDepth(0);

    this.ySort.add([ this.player, ...this.chests, ...this.trees ]);
}

update ()
{
    this.ySort.each(child => child.setDepth(child.y));
}
```

`Layer` "acts as a Display List", children's `setDepth` adjusts depth "within the Layer itself, rather than the whole Scene", and `LayerWebGLRenderer` calls `layer.depthSort()` per render ([`Layer.js` classdesc](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/layer/Layer.js), [`LayerWebGLRenderer.js#L39`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/layer/LayerWebGLRenderer.js#L39)). Caveats from the classdesc: Layers have no position/size, cannot be enabled for physics or input, and "Layers should always be the topmost elements of any scene hierarchy" (they can nest in Layers but not in Containers).

Two practical points:

1. **Set `setOrigin(0.5, 1)` on everything sortable** so `y` is the base of the sprite, i.e. where the feet touch the ground. Otherwise `depth = y` sorts by the sprite's center and a tall tree will sort wrong.
2. `Layer.each` allocates nothing per call and the sort is stable, so calling it every frame for a few dozen objects is fine. If the farm grows to hundreds of objects, sort only when something moved.

## 5. "Player is standing next to this chest"

Three options, in increasing fidelity. All three are cheap; I would use **B**.

### A. Distance check (simplest, no physics)

```js
const near = this.chests.find(c =>
    Phaser.Math.Distance.Between(this.player.x, this.player.y, c.x, c.y) < 24);
```
`Phaser.Math.Distance.Between` exists at [`src/math/distance/DistanceBetween.js`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/math/distance/DistanceBetween.js). Downside: circular, so you can trigger a chest while standing on the wrong side of a fence.

### B. Arcade overlap against an interaction Zone (recommended)

A `Zone` is "a non-rendering rectangular Game Object that has a position and size but no texture... also useful for object overlap checks" ([`Zone.js` classdesc](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/zone/Zone.js)).

```js
create ()
{
    this.nearbyChest = null;

    this.chests = map.getObjectLayer('Chests').objects.map(o => {
        const sprite = this.physics.add.staticSprite(o.x, o.y, 'chest');
        sprite.setOrigin(0.5, 1);
        sprite.setData('chestId', o.properties?.find(p => p.name === 'chestId')?.value);

        // interaction zone: one tile wider and taller than the chest
        const zone = this.add.zone(o.x, o.y - 8, 32, 32);
        this.physics.add.existing(zone, true);        // true = static body
        zone.setData('chest', sprite);
        return sprite;
    });

    this.physics.add.overlap(this.player, this.chestZones, (_player, zone) => {
        this.nearbyChest = zone.getData('chest');
    });

    this.interactKey = this.input.keyboard.addKey(Phaser.Input.Keyboard.KeyCodes.E);
}

update ()
{
    const wasNear = this.nearbyChest;
    this.nearbyChest = null;          // cleared each frame; the overlap re-sets it

    // ... movement ...

    if (this.nearbyChest && Phaser.Input.Keyboard.JustDown(this.interactKey))
    {
        openChestUI(this.nearbyChest.getData('chestId'));
    }
}
```

Two ordering details that matter: Arcade overlaps are evaluated during `physics.world.update`, which runs **before** the scene's `update` in the step, so clearing `this.nearbyChest` at the top of `update` and reading it at the bottom would clear the flag before you use it. Safer is to clear it in a `POST_UPDATE` handler, or to track `lastOverlapFrame` and compare against `this.game.loop.frame`. **I did not verify the exact ordering in Phaser 4's source**, so test this rather than trusting the snippet's ordering as written.

`Phaser.Input.Keyboard.JustDown(key)` is the correct "fire once per press" helper ([input skill](https://github.com/phaserjs/phaser/blob/master/skills/input-keyboard-mouse-touch/SKILL.md)).

### C. Facing-aware tile probe (most Stardew-accurate)

Stardew actually checks the tile *in front of you*. With a tilemap you get this for free:

```js
const dir = { up: [0,-1], down: [0,1], left: [-1,0], right: [1,0] }[this.facing];
const t = propsLayer.getTileAtWorldXY(
    this.player.x + dir[0] * 16,
    this.player.y - 8 + dir[1] * 16
);
if (t?.properties?.chestId) { /* prompt */ }
```
`getTileAtWorldXY` and `tile.properties` (custom properties from Tiled) are both documented in the [tilemaps skill](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md).

**For the prompt itself**, keep it in canvas (a small Phaser sprite or BitmapText above the chest), not HTML. It has no text entry, it must track a world position pixel-exactly, and rendering it in DOM means fighting the coordinate transform every frame for no benefit.

## 6. THE KEY ONE: HTML/CSS DOM UI over the Phaser canvas

### Phaser `DOMElement` vs a plain overlay div

**Verdict: plain overlay div. `DOMElement` is the wrong tool for todoFarm.**

What `DOMElement` gives you: DOM nodes that live in a Phaser-managed container, respect camera scroll and `scrollFactor`, can be tweened with Phaser tweens, and even accept an Arcade body (see the official [`dom element/cursors test.js`](https://github.com/phaserjs/examples/blob/master/public/src/game%20objects/dom%20element/cursors%20test.js)). It requires `parent` plus `dom: { createContainer: true }` in config; **in v4 it now throws** if the container is missing ([`DOMElement.js#L133-L136`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/domelement/DOMElement.js#L133), and [migration guide section 21](https://github.com/phaserjs/phaser/blob/master/changelog/v4/4.0/MIGRATION-GUIDE.md)).

Why it is wrong here, each point sourced:

| Problem | Evidence |
|---|---|
| **Your UI gets CSS-scaled by the zoom factor.** The ScaleManager writes `domStyle.transform = 'scale(' + displaySize.width / baseSize.width + ',' + ...)` on the DOM container. At `zoom: 3` your chat panel renders at 3x with `transform-origin: left top`, so all your CSS pixel values are lies and your fonts are scaled bitmaps. | [`ScaleManager.js#L987`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/ScaleManager.js#L987), container created with `transform: scale(1); transform-origin: left top` at [`CreateDOMContainer.js#L45-L46`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/dom/CreateDOMContainer.js) |
| **Cannot interleave with sprites.** "You cannot blend them into the display list, meaning you cannot have a DOM Element, then a Sprite, then another DOM Element behind it." | [docs.phaser.io DOM Element](https://docs.phaser.io/phaser/concepts/gameobjects/dom-element) |
| **No Phaser input.** "They also cannot be enabled for input. To do that, you have to use the `addListener` method to add native event listeners directly." | same page; see the `element.addListener('click')` dance in [`dom element/form input.js`](https://github.com/phaserjs/examples/blob/master/public/src/game%20objects/dom%20element/form%20input.js) |
| **Single-camera restriction.** "You should only have DOM Elements in a Scene with a _single_ Camera." | same page |
| **All DOM Elements share one container regardless of scene.** | [`DOMElement.js` classdesc](https://github.com/phaserjs/phaser/blob/v4.2.1/src/gameobjects/domelement/DOMElement.js) |
| **`dom.behindCanvas` is documented but not wired.** The typedef advertises it ([`DOMContainerConfig.js#L6`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/typedefs/DOMContainerConfig.js#L6)) and the API docs list it, but `Config.js` only reads `dom.createContainer` and `dom.pointerEvents` ([`Config.js#L209`, `#L214`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L209)). Setting it does nothing. | grepped the whole `src/` tree; the string appears only in the typedef |

And the positive case: Phaser Studio's own framework templates, all updated for Phaser 4, render UI as ordinary sibling DOM and communicate through a tiny event emitter, not `DOMElement`. See [`template-react`](https://github.com/phaserjs/template-react) (README: "This template has been updated for Phaser 4"), whose [`src/game/main.js`](https://github.com/phaserjs/template-react/blob/main/src/game/main.js) just sets `parent: 'game-container'` with no `dom` block at all, and whose [`EventBus.js`](https://github.com/phaserjs/template-react/blob/main/src/game/EventBus.js) is the documented bridge:

```js
// In React
import { EventBus } from './EventBus';
EventBus.emit('event-name', data);

// In Phaser
EventBus.on('event-name', (data) => { /* ... */ });
```

That is the officially blessed pattern for HTML UI over a Phaser 4 canvas. Same structure exists for [Vue](https://github.com/phaserjs/template-vue), [Svelte](https://github.com/phaserjs/template-svelte), [Angular](https://github.com/phaserjs/template-angular), and [Solid](https://github.com/phaserjs/template-solid).

Where you might still want `DOMElement`: nothing in todoFarm that I can see. Possibly a hover tooltip pinned to a chest in world space, and even that is easier as canvas text.

### The overlay layout

```html
<body>
  <div id="app">
    <div id="game-container"></div>   <!-- Phaser owns this -->
    <div id="ui-root" inert></div>    <!-- you own this -->
  </div>
</body>
```

```css
#app { position: relative; width: 100vw; height: 100vh; overflow: hidden;
       display: flex; align-items: center; justify-content: center; background: #000; }

#game-container { /* Phaser writes canvas width/height/margin; do not fight it */ }

#ui-root {
  position: absolute; inset: 0;
  pointer-events: none;             /* clicks fall through to the canvas by default */
  font-family: 'YourPixelFont', system-ui, sans-serif;
}
#ui-root .panel { pointer-events: auto; }   /* only real panels capture input */
#ui-root[inert] { opacity: 0; }
```

Critical CSS constraint from the official [scale skill's gotchas](https://github.com/phaserjs/phaser/blob/master/skills/scale-and-responsive/SKILL.md): **"Do not style the canvas directly. The ScaleManager controls `canvas.style.width`, `canvas.style.height`, `marginLeft`, and `marginTop`. External CSS on the canvas will conflict."** Also: "Parent element must have dimensions... An unstyled `<div>` has zero height, which breaks centering and scaling", and "No padding on the parent. The ScaleManager does not account for parent padding."

`inert` makes an element and its subtree unfocusable, unclickable, and invisible to screen readers and find-in-page. It is Baseline "widely available" since April 2023, so it is safe in a 2026 WKWebView ([MDN `inert`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/inert)).

**Note that your UI text is NOT pixel-scaled.** This is the whole point of the overlay: the canvas renders at 480x270 upscaled 3x by CSS, while `#ui-root` renders at full device resolution. Your NPC dialogue is crisp subpixel-antialiased text, and your farm is chunky pixels. If you want the pixel-font *look*, load a real pixel webfont at an integer size (`font-size: 16px` with `image-rendering` untouched), do not scale a 8px font up.

### The keyboard handoff, the part you actually have to get right

**The problem, verified in source.** Asymmetry in default event targets:

- Keyboard: `this.inputKeyboardEventTarget = GetValue(config, 'input.keyboard.target', window)` ([`Config.js#L226`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L226)); `if (!this.target && window) { this.target = window; }` ([`KeyboardManager.js#L162-L165`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardManager.js#L162)), then `target.addEventListener('keydown', this.onKeyDown, false)` ([#L230](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardManager.js#L230)).
- Mouse: `if (!this.target) { this.target = this.manager.game.canvas; }` ([`MouseManager.js#L252-L255`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/mouse/MouseManager.js#L252)).

The `keydown` handler queues **every** event that is not already `defaultPrevented`, with no check on `event.target` ([`KeyboardManager.js#L184-L200`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardManager.js#L184)), and `KeyboardPlugin.update` likewise never inspects `event.target` ([`KeyboardPlugin.js` update loop](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js)). Keydowns from an `<input>` bubble to `window`. **So typing into your inbox field moves your character.**

Also note `preventDefault` is only applied to key codes in the `captures` array ([`KeyboardManager.js#L196-L199`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardManager.js#L196)), which by default is empty ([`Config.js#L231`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L231)). So the reverse direction is fine out of the box: Phaser will not eat your keystrokes unless you ask it to.

**The fix: a single mode gate.** Do not try to be clever with `event.target` filtering; flip Phaser's keyboard off wholesale when the overlay owns focus.

```js
// src/ui/focus.js
let phaserScene = null;
export const bindScene = (s) => { phaserScene = s; };

export function setUIMode (uiActive)
{
    const root = document.getElementById('ui-root');
    root.inert = !uiActive;                       // unfocusable + unclickable when closed

    if (!phaserScene) return;
    const kb = phaserScene.input.keyboard;

    if (uiActive)
    {
        kb.resetKeys();          // clear any key stuck 'down' from the keypress that opened the UI
        kb.enabled = false;      // KeyboardPlugin.isActive() -> false, update() early-returns
        kb.disableGlobalCapture();
        root.querySelector('input, textarea, [tabindex]')?.focus();
    }
    else
    {
        kb.enabled = true;
        kb.enableGlobalCapture();
        kb.resetKeys();          // and again on the way out
        document.activeElement?.blur();
    }
}
```

Everything used here is real public API:
- `this.input.keyboard.enabled = false` is the officially documented way to stop a scene stealing keys: "You can do this with `this.input.keyboard.enabled = false` within the Scene to stop all input" ([`KeyboardPlugin.js#L48`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js#L48)). It gates `isActive()`, which gates `update()`.
- `resetKeys()` walks every `Key` and calls `reset()` ([`KeyboardPlugin.js#L853`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js#L853)). **You need this or keys get stuck.** Phaser itself calls it on `GameEvents.BLUR`, `SceneEvents.PAUSE`, and `SceneEvents.SLEEP` ([`KeyboardPlugin.js#L224-L227`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js#L224)) for exactly this reason.
- `enableGlobalCapture()` / `disableGlobalCapture()` are documented public methods ([`KeyboardPlugin.js#L346-L370`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js#L346)).

**Two more focus landmines, both source-verified:**

1. **`autoFocus` defaults to `true` and calls `window.focus()` on every canvas mousedown/touchstart**, not just at boot: `this.autoFocus = GetValue(config, 'autoFocus', true)` ([`Config.js#L190`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L190)), used in [`MouseManager.js#L380-L385`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/mouse/MouseManager.js#L380) and [`TouchManager.js#L258-L263`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/touch/TouchManager.js#L258). In a Tauri window this is mostly harmless (`window.focus()` does not blur the active element within the window), but if you see focus jump when clicking the farm, set `autoFocus: false` first.
2. **Phaser calls `event.preventDefault()` on canvas mousedown** when `input.mouse.preventDefaultDown` is true (the default, [`Config.js#L246`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L246)) and `event.target === canvas`. Preventing default on mousedown suppresses the browser's focus change, so **clicking the farm will not blur your open text input**. You must call `.blur()` yourself, as the snippet above does.

**A stricter alternative I did not test.** Point Phaser's keyboard at the canvas and make the canvas focusable:

```js
// game config
input: { keyboard: { target: document.getElementById('game-canvas') } }
```
Phaser reads `input.keyboard.target` ([`Config.js#L226`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L226)), so this works mechanically. But Phaser never sets `tabindex` on the canvas (grepping `src/` for `tabindex`/`tabIndex` finds only `GameObject#tabIndex`, an unrelated property), so a canvas cannot receive DOM focus without you adding `tabindex="0"`, and you would then be managing canvas focus by hand and fighting focus rings. **The `keyboard.enabled` gate is simpler and is what Phaser's own docstring recommends.** Consider the target approach only if you find the gate leaking.

### Passing data both ways

Copy Phaser's own `EventBus` pattern from [`template-react/src/game/EventBus.js`](https://github.com/phaserjs/template-react/blob/main/src/game/EventBus.js). It is literally `new Phaser.Events.EventEmitter()` exported as a module singleton. For todoFarm:

```js
// Phaser -> UI
EventBus.emit('chest-opened', { chestId, worldX: chest.x, worldY: chest.y });

// UI -> Phaser
EventBus.emit('chest-closed');
EventBus.emit('chest-created', { chestId, name, tileX, tileY });  // NPC invents a new category
```

The template README warns to emit `'current-scene-ready'` at the end of each scene's `create()` so the UI layer always has a live scene reference.

### Anchoring an HTML element to a world position (if you need it)

If you decide a panel must sit over a specific chest, the conversion is:

```js
function worldToCss (scene, worldX, worldY)
{
    const cam = scene.cameras.main;
    const sm = scene.game.scale;
    const gx = (worldX - cam.scrollX) * cam.zoom;   // game px within the canvas
    const gy = (worldY - cam.scrollY) * cam.zoom;
    return {
        left: sm.canvasBounds.x + gx / sm.displayScale.x,
        top:  sm.canvasBounds.y + gy / sm.displayScale.y
    };
}
```
`canvasBounds` is the canvas's `getBoundingClientRect` plus page offsets ([`ScaleManager.updateBounds`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/ScaleManager.js)), and `displayScale` is set as `baseSize.width / canvasBounds.width` ([`ScaleManager.js#L976`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/ScaleManager.js#L976)), i.e. game pixels per CSS pixel. **I derived this formula from the source rather than from a documented example; verify it empirically before relying on it.** My advice remains to avoid needing it.

## Consolidated gotcha list

Ordered by how likely each is to cost you an afternoon.

1. **`camera.setZoom(n)` silently disables default vertex rounding.** Use `scale.zoom` instead. ([`TransformerImage.js#L182`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/renderer/webgl/renderNodes/transformer/TransformerImage.js#L182))
2. **Typing in HTML inputs moves the player** until you gate `input.keyboard.enabled`. ([`KeyboardManager.js#L164`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardManager.js#L164))
3. **`Phaser.Scale.MAX_ZOOM` is resolved once at boot** and never on resize. Call `game.scale.setMaxZoom()` in a resize listener. ([`ScaleManager.js#L556`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/ScaleManager.js#L556))
4. **`roundPixels` now defaults to `false`** in Phaser 4. `pixelArt: true` turns it back on. ([`Config.js#L382`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js#L382))
5. **Keys stick down** if you disable the keyboard mid-press. Always `resetKeys()` on both edges of the mode switch. ([`KeyboardPlugin.js#L853`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/input/keyboard/KeyboardPlugin.js#L853))
6. **If you configure cameras via scene settings JSON, `roundPixels` is forced to `false`** unless you name it explicitly: `camera.roundPixels = GetFastValue(cameraConfig, 'roundPixels', false)` ([`CameraManager.js#L427`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/cameras/2d/CameraManager.js#L427)). The default main camera created by `add()` is unaffected.
7. **Do not put CSS on the canvas element.** The ScaleManager owns `width`, `height`, `marginLeft`, `marginTop`. ([scale skill gotcha 3](https://github.com/phaserjs/phaser/blob/master/skills/scale-and-responsive/SKILL.md))
8. **The parent div needs explicit dimensions and no padding.** ([scale skill gotchas 1 and 2](https://github.com/phaserjs/phaser/blob/master/skills/scale-and-responsive/SKILL.md))
9. **Tiled "Collection of Images" tilesets do not parse.** One image per tileset. ([tilemaps skill](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md))
10. **No TMX support.** JSON only. (no XML parser exists in [`src/tilemaps/parsers/`](https://github.com/phaserjs/phaser/tree/v4.2.1/src/tilemaps/parsers))
11. **`dom.behindCanvas` is a no-op** despite being in the docs and typedef. ([`Config.js`](https://github.com/phaserjs/phaser/blob/v4.2.1/src/core/Config.js) reads only `createContainer` and `pointerEvents`)
12. **`Phaser.WEBGL` has no Canvas fallback** and fails silently; use `Phaser.AUTO`. ([setup skill gotcha 2](https://github.com/phaserjs/phaser/blob/master/skills/game-setup-and-config/SKILL.md))
13. **Default game dimensions changed in v4** to 1024x768 from 800x600. Set them explicitly. ([setup skill, v4 changes](https://github.com/phaserjs/phaser/blob/master/skills/game-setup-and-config/SKILL.md))
14. **`createLayer` on the same layer ID twice returns `null`.** ([tilemaps skill gotcha 3](https://github.com/phaserjs/phaser/blob/master/skills/tilemaps/SKILL.md))

## What I could not confirm

Stated plainly so you do not over-trust the above.

- **I did not run any of this code.** Everything is read from Phaser 4.2.1's source, its official skill docs, and its official examples. The pixel-perfect claims in section 1 in particular deserve a 30-minute empirical check: build a scene with a diagonal-moving sprite over a tilemap at `scale.zoom: 3` and again at `camera.setZoom(3)`, and compare.
- **The Arcade overlap ordering in section 5B** (whether `physics.world.update` runs before `Scene.update` in Phaser 4's step) I did not verify in source. Test the clear-and-set pattern before shipping it.
- **The `worldToCss` formula** is derived from `displayScale` and `canvasBounds` semantics in source, not from a documented example. Verify.
- **`vertexRoundMode: 'fullAuto'` under camera zoom** is a reasoned inference about how nearest-neighbour sampling behaves at integer zoom, not a verified visual result.
- **No official Phaser 4 example exists for "HTML overlay UI with keyboard mode switching."** The closest official artifacts are the framework templates (sibling DOM + EventBus) and [`dom element/form input.js`](https://github.com/phaserjs/examples/blob/master/public/src/game%20objects/dom%20element/form%20input.js) (the `DOMElement` approach you should not use). The mode-gate pattern in section 6 is assembled from documented primitives, not copied from an official sample.
- **I could not use WebSearch** (this session's search budget was exhausted before my first call), so I could not survey 2026 community blog posts or Discord threads for field-tested pixel-art recipes. Every claim above traces to a primary source I fetched directly: the Phaser GitHub repo at tag `v4.2.1`, the `phaserjs/examples` and `phaserjs/template-*` repos, `docs.phaser.io`, the npm registry, and MDN. If you want the community cross-check, that is the one gap worth filling with a follow-up search.
- **Phaser 3's maintenance status.** [phaser.io/download/stable](https://phaser.io/download/stable) still hosts a Phaser 3 download page, and the fetch summary read that as "both remain supported options", but I found no explicit Phaser Studio statement about long-term v3 support or an end-of-life date. # Adversarial fact-check

I verified ~60 discrete claims against primary sources. Writing up findings.

## Corrections

Very few. I fetched every load-bearing URL and grepped the actual v4.2.1 source with `curl` + `grep -n` rather than trusting a summarizer (which, notably, miscounted line numbers by ~200 on my first pass — the report's anchors were right and the summarizer was wrong).

**1. Section 5B's code is confirmed broken, not merely "unverified."** The report hedges: *"I did not verify the exact ordering in Phaser 4's source."* I verified it, and the fear is correct — the snippet as written can never fire.

- `Systems.step` order is: `PRE_UPDATE` → `UPDATE` → `sceneUpdate` → `POST_UPDATE` ([Systems.js](https://raw.githubusercontent.com/phaserjs/phaser/v4.2.1/src/scene/Systems.js), `step:` body).
- `ArcadePhysics` binds `world.update` to `SceneEvents.UPDATE` (L142 and L159), and `world.postUpdate` to `POST_UPDATE` (L145) — [ArcadePhysics.js](https://raw.githubusercontent.com/phaserjs/phaser/v4.2.1/src/physics/arcade/ArcadePhysics.js).
- Overlap callbacks fire inside `World.update`/`World.step`, which process colliders at L986 and L1040 (`this.colliders.update()` → `collider.update()`) — [World.js](https://raw.githubusercontent.com/phaserjs/phaser/v4.2.1/src/physics/arcade/World.js). `World.postUpdate` (L1077) only syncs transforms.

So overlap callbacks run **before** your `update()`. Clearing `this.nearbyChest = null` at the top of `update()` wipes the value set earlier that same frame; the read at the bottom is always `null` and the chest never opens. The report's own suggested remedies (clear in `POST_UPDATE`, or compare `lastOverlapFrame` against `game.loop.frame`) are the right fixes — they just need to be treated as required, not optional.

**2. `setMaxZoom` line anchor is wrong.** The report cites [ScaleManager.js#L1184](https://github.com/phaserjs/phaser/blob/v4.2.1/src/scale/ScaleManager.js#L1184) for "`setMaxZoom()` and `getMaxZoom()`". L1184 is `getMaxZoom`; `setMaxZoom` is at **L912**. Both methods are real and public, so the claim holds — only the deep link is off.

**3. `applyITRS` line anchor is wrong.** The report attributes `matrix.applyITRS(originX, originY, this.rotation, zoomX, zoomY)` to [Camera.js#L535 "preRender"](https://github.com/phaserjs/phaser/blob/v4.2.1/src/cameras/2d/Camera.js#L535). L535 is the `renderRoundPixels` line (the report's *other* citation, which is correct). `applyITRS` is at **L630**, inside `getViewMatrix`. Substance unaffected — camera zoom does enter the composed matrix.

**4. Minor imprecision:** "28 official AI-agent skill **files**" — there are 28 skill **directories**, each containing a `SKILL.md`. Count and every named skill verified correct.

**5. Copy-the-template caveat:** `phaserjs/template-react` pins `"phaser": "4.0.0"`, not 4.2.1. The "updated for Phaser 4" claim is true; a reader cloning it gets 4.0.0.

## Unverifiable claims

- **All visual/empirical claims** — the report is upfront about these and I could not close them either: actual crispness at `scale.zoom` vs `camera.setZoom`, how `vertexRoundMode: 'fullAuto'` looks under camera zoom, and the `worldToCss` formula. The formula's inputs are right (`displayScale` is set as `baseSize.width / canvasBounds.width` at L976, i.e. game px per CSS px), but the composed arithmetic is untested.
- **The tilemap-shimmer-at-fractional-scroll claim** and the `POST_UPDATE` camera-scroll-flooring workaround. Mechanically plausible, no official example, not tested.
- **Phaser 3's maintenance status.** I confirmed phaser.io/download/stable still offers Phaser 3 alongside 4, but like the report I found no EOL statement. "Maintenance-only" remains inference.
- I could not run WebSearch either — this session's 200-call budget was already exhausted before my first call, the same gap the report discloses. So the community cross-check is *still* unfilled, and neither of us has surveyed 2026 field reports.

## Omissions

**1. `smoothPixelArt` is never mentioned — the biggest gap.** Phaser 4 ships a config flag built specifically for scaled-up pixel art, and a report whose entire section 1 is about pixel-art crispness omits it. `Config.js` L407–415 sets `antialias: true`, `antialiasGL: true`, `pixelArt: false`; the official setup skill has a dedicated *"Smooth Pixel Art (WebGL only)"* section: *"Preserves blocky pixels but smooths edges between them when scaled up."* It's listed in the config table (L321) with its own gotcha (#8, WebGL-only). This is a genuine alternative to the `pixelArt: true` route and deserved at least a paragraph explaining why todoFarm should or shouldn't take it.

**2. The report under-cites its own best finding.** The migration guide states the camera-zoom rule in plain prose at L329: *"`roundPixels` only operates when objects are axis-aligned and unscaled, preventing flicker on transforming objects."* The report derived this from reading transformer source and flagged it as needing empirical verification — when official documentation already asserts it. Finding #2 is better supported than the report claims.

**3. Tiled export requires embedded tilesets.** Tilemaps skill gotcha 7: *"Embedded tilesets in the exported JSON are required."* If you export from Tiled with an external `.tsx` reference, the map will not parse. This is exactly the kind of thing that costs an afternoon and belongs on the consolidated gotcha list.

**4. No devicePixelRatio / Retina discussion — and this is a macOS-first app.** Phaser 4 has *zero* DPR handling: no `devicePixelRatio` or `resolution` reference anywhere in `ScaleManager.js` or `Config.js`. At integer DPR this is fine (the 480×270 backing store is CSS-upscaled and `image-rendering: pixelated` keeps it crisp). But macOS "scaled" display modes — the default on many MacBooks — composite through a fractional downsample that can soften pixel art no matter what Phaser does. `getMaxZoom` snaps to integers in *CSS* pixels only. This deserved a flag, and a test on a scaled Retina mode.

**5. Nothing on the Tauri asset pipeline.** The stack is decided (Tauri v2 shipping the `.app`), yet the report never covers how Phaser loads `maps/farm.tmj` and spritesheets inside WKWebView — `asset:` protocol vs bundled dev server vs `file://` — nor confirms WebGL1 availability in Tauri's macOS WKWebView. It correctly flags template-tauri as Phaser-3-pinned but then leaves the wiring question open.

**6. `SpriteGPULayer`** appears in the same v4.0.0 release notes as `TilemapGPULayer` (*"Render a million sprites in a single draw call"*). Almost certainly unnecessary for a small farm, but it went unmentioned while its sibling got a section.

**7. Two small ones:** `roundPixels` explicitly does not apply to textureless objects — Config.js L380: *"Game Objects without textures, like Graphics, ignore this property"* — relevant if any in-canvas UI is drawn with Graphics. And MIT compliance for a commercial `.app` requires shipping the copyright notice; the report establishes MIT but never states the obligation.

**One thing I expected to be a bug and wasn't:** the recipe `window.addEventListener('resize', () => game.scale.setMaxZoom())` looks like it should read a stale `parentSize`, since `getMaxZoom()` reads `this.parentSize` and the ScaleManager only polls every `resizeInterval` (default 500ms). It works anyway — Phaser registers its own `window` resize listener at boot (which calls `getParentBounds()` then `refresh()`), and DOM listeners fire in registration order, so Phaser refreshes `parentSize` before your handler runs. Correct, but for a non-obvious reason worth knowing if you ever reorder initialization. I also confirmed `mode: NONE` + `autoCenter` works: `updateScale` calls `updateCenter()` on every path regardless of scale mode.

## Net assessment

**Trustworthy, and unusually so.** I set out to find errors and found four minor citation slips and one confirmed code bug that the report had already flagged as uncertain. There are **no license errors** — the highest-stakes category — and no invented versions, dates, prices, or URLs. Every version number and date is exact to the day. Every quoted docs string I checked is verbatim, not paraphrased. Line anchors into a specific git tag are the most fragile thing a report like this can do, and roughly 40 of them are dead-on.

The report's epistemic hygiene is the reason to trust it: it consistently marks derived-from-source reasoning as unverified, and its "What I could not confirm" section is accurate rather than decorative. Two of its self-flagged uncertainties I was able to resolve — the physics ordering (its worry was justified, the snippet is broken) and the camera-zoom rounding rule (better supported than it claimed).

Use recommendations 1–5 as written, with three changes: fix the 5B overlap-clearing bug before writing it, evaluate `smoothPixelArt` before committing to `pixelArt: true`, and embed your tilesets on Tiled export. Do not skip the report's own advice to spend 30 minutes empirically checking section 1 — the mechanism is proven, the visual result is not, and the DPR question makes that test more important on macOS than the report implies.
