# Minecraft's art standardisation, and what to copy

## Part 1: How Minecraft Actually Standardises Its Art

### Sourcing note up front

Mojang does not publish a formal, versioned resource pack specification. The de facto reference is **minecraft.wiki** (community-maintained, formerly the Gamepedia/Fandom wiki), supplemented by Mojang's own snapshot articles and two official GitHub repos. Everything below is cited. Where a widely repeated community claim did not survive checking against a primary source, I say so explicitly rather than repeating it.

---

### 1. The resource pack format

**Directory layout** ([Resource pack](https://minecraft.wiki/w/Resource_pack), [Tutorial:Creating a resource pack](https://minecraft.wiki/w/Tutorial:Creating_a_resource_pack)):

```
PackName/  (or PackName.zip)
├── pack.mcmeta          (mandatory; its presence is what makes this a pack)
├── pack.png             (optional icon, 128x128 recommended)
└── assets/
    └── <namespace>/
        ├── atlases/
        ├── blockstates/
        ├── font/
        ├── items/       (1.21.4+ item model definitions)
        ├── lang/
        ├── models/
        │   ├── block/
        │   └── item/
        ├── sounds/
        └── textures/
            ├── block/
            ├── item/
            ├── entity/
            └── gui/sprites/
```

The tutorial is emphatic that `assets/`, `pack.mcmeta`, and `pack.png` "should be the only files located directly in your parent resource pack folder." A common real-world failure is zipping a wrapper folder instead of the pack contents at the archive root.

**pack.mcmeta.** Modern form, quoted verbatim from the wiki tutorial:

```json
{
    "pack": {
        "description": "This is the description of your resource pack.",
        "min_format": 88,
        "max_format": 88
    }
}
```

Fields ([pack.mcmeta](https://minecraft.wiki/w/Pack.mcmeta)): `description` (a text component), the legacy `pack_format` integer, `min_format` / `max_format` (integer or `[major, minor]` array), and optional `supported_formats`. Beyond `pack`, there are optional `features.enabled` (experimental flags), `filter.block` (array of `{namespace, path}` regex patterns that exclude files from packs loaded earlier), `overlays.entries` (sub-pack directories, each with its own format range, which is how one download supports several game versions), and `language`.

**pack_format numbers** ([Pack format](https://minecraft.wiki/w/Pack_format)). Resource pack formats:

| Format | Java Edition |
|---|---|
| 1 | 1.6.1 – 1.8.9 |
| 4 | 1.13 – 1.14.4 |
| 9 | 1.19 – 1.19.2 |
| 15 | 1.20 – 1.20.1 |
| 18 | 1.20.2 |
| 22 | 1.20.3 – 1.20.4 |
| 32 | 1.20.5 – 1.20.6 |
| 34 | 1.21 – 1.21.1 |
| 42 | 1.21.2 – 1.21.3 |
| 46 | 1.21.4 |
| 55 | 1.21.5 |
| 64 | 1.21.7 – 1.21.8 |
| 69.0 | 1.21.9 – 1.21.10 |
| 75.0 | 1.21.11 |
| 84.0 | 26.1 – 26.1.2 |
| 88.0 | 26.2 |

**The single most important architectural fact here:** the format number is not the game version, not the resolution, and not a semver. It is an opaque counter that increments whenever the asset contract changes. Formats jump irregularly (15, 18, 22, 32, 34) because they tick on snapshots too. If the number exceeds what the client knows, the pack is listed as "incompatible" and simply does not load. Since 1.21.9 the format carries a minor component, and Mojang has been migrating packs from a single `pack_format` toward the `min_format` / `max_format` range.

**Namespaces.** `assets/<namespace>/`. The `minecraft` namespace overrides vanilla files; any other namespace adds new content without collision risk. Resource locations are written `namespace:path` and resolve mechanically to `assets/<namespace>/<type>/<path>.<ext>`. So `minecraft:block/stone` in a model's `textures` map resolves to `assets/minecraft/textures/block/stone.png`.

Path charset is constrained: `[a-z0-9-_.]` for namespaces, `[a-z0-9-_./]` for paths (this is what the community [ResourcePackValidator](https://github.com/MrKinau/ResourcePackValidator) `InvalidPathValidator` enforces). The wiki tutorial states the underlying rule: "In versions 1.11 and higher, all file names within a resource pack must use lowercase letters only."

### 2. Texture conventions and the powers-of-two question

**Base resolution.** The [Textures](https://minecraft.wiki/w/Textures) page states blocks "are usually done in 16×16 pixels" and items "are also done in 16×16 pixels." Entity textures are higher resolution "but typically their heights and widths are multiples of 16px." Note the word *usually*. This is convention, not enforcement.

**What is actually enforced.** This is where most secondhand explanations get it wrong. The [Atlas](https://minecraft.wiki/w/Atlas) page gives the real rule:

> "For atlases which support mipmapping, all sprites should be a minimum of 16x16 pixels in size and a multiple of 2. If these guidelines aren't met the maximum mipmap level is limited and a message is printed in the log."

So higher-resolution packs (32x, 64x, 128x, 256x) are a *convention that satisfies a softer technical constraint*. Nothing rejects a 24x pack. What happens is that the maximum usable mipmap level drops, the game logs it, and distant textures (leaves especially) render at lower quality. The `TextureLimitMipLevelValidator` in ResourcePackValidator makes the practical threshold concrete: "For mip mapping to work (for mip map level 4) you need to have a texture size of at least 16x16, height and width should be divisible by 16 without a remainder."

**I could not confirm from any primary source the widely repeated claim that Minecraft *requires* power-of-two textures.** Minecraft Forum threads assert it; the wiki and Mojang do not. The accurate statement is: non-conforming sizes degrade mipmapping globally for the atlas rather than failing. That distinction matters for our own spec, and I take the opposite position below on purpose.

**Other texture facts.** Pre-1.13, block and item textures had to be square to function at all. As of 1.13, "non-square textures can be used for blocks and items just fine (although they will look stretched/squashed on default models)." As of 1.20.3-pre1, "the only supported texture format is now `.png`."

**Resolution independence, the good idea.** From [Tutorial:Models](https://minecraft.wiki/w/Tutorial:Models), UV coordinates in model JSON always run on a 0..16 grid expressed as percentages, regardless of the actual PNG size:

> "Because this works in percentages, resizing an image from 16×16 to 32×32, 64×64, etc., does not require changing the model file."

This one decision is why a 512x pack and a 16x pack can share every single model file in the game. It is the most transferable idea in the entire system.

**Failure mode.** When a referenced texture does not exist, Minecraft draws the [missing texture](https://minecraft.wiki/w/Missing_texture): a checkerboard of black `#000000` and magenta `#f800f8` in Java Edition. It is deliberately hideous so it cannot ship unnoticed.

### 3. Animated textures

Animation is a **sidecar file**, not a baked-in convention. `stone.png` is accompanied by `stone.png.mcmeta` in the same directory ([Mcmeta](https://minecraft.wiki/w/Mcmeta), [Resource pack](https://minecraft.wiki/w/Resource_pack)):

```json
{
  "animation": {
    "interpolate": false,
    "width": 16,
    "height": 16,
    "frametime": 1,
    "frames": [0, {"index": 1, "time": 3}, 2]
  }
}
```

| Field | Behaviour |
|---|---|
| `frametime` | "Sets the default time for each frame in increments of one game tick. Defaults to `1`." One tick is 1/20 second. |
| `interpolate` | "If true, the game generates additional frames between frames if the `frametime` is greater than 1 between them. Defaults to `false`." |
| `width` / `height` | Dimensions of a single frame. If omitted, "the game assumes each frame is square and the size of the smallest dimension of the image." |
| `frames` | List of frame indices. Defaults to all frames, first to last. Entries are either an integer or `{"index": i, "time": t}`, where `time` overrides `frametime` for that entry. |

**Layout.** Frames are placed "either vertically below the first, or horizontally to the right of the first." With explicit `width`/`height` they read "row by row, top to bottom, left to right." The vertical strip is the default because omitting `width`/`height` on a 16x160 PNG unambiguously yields ten 16x16 frames with zero configuration.

**Hard constraint:** "The total dimensions of the image must be divisible by the `width` and `height`" or the missing texture displays instead.

Two things worth stealing: per-frame `time` overrides mean an artist can hold a pose without drawing duplicate frames, and timing lives in a data file the artist edits rather than in engine code an engineer edits.

### 4. Models, and how a texture binds to a model

Models live at `assets/<namespace>/models/block/*.json` and `.../item/*.json` ([Model](https://minecraft.wiki/w/Model)).

Binding is a three-step indirection: a model declares **texture variables**, faces reference them with `#`, and the variable's value is a resource location.

```json
{
  "parent": "block/cube_all",
  "textures": {
    "all": "minecraft:block/stone"
  }
}
```

```json
{
  "textures": {
    "side": "minecraft:block/oak_log_side",
    "top": "minecraft:block/oak_log_top",
    "particle": "minecraft:block/oak_log_side"
  },
  "elements": [
    {
      "from": [0, 0, 0],
      "to": [16, 16, 16],
      "faces": {
        "north": {"uv": [0, 0, 16, 16], "texture": "#side"},
        "up":    {"uv": [0, 0, 16, 16], "texture": "#top"}
      }
    }
  ]
}
```

`parent` gives inheritance, so a whole family of blocks is one line of JSON plus one texture path. `particle` names the texture used for break particles; since 1.21.5 the game logs a warning if it is undefined. Blockstate files at `assets/<ns>/blockstates/*.json` map block states to models with optional rotation:

```json
"variants": {
    "facing=east":  { "model": "block/wall_torch" },
    "facing=south": { "model": "block/wall_torch", "y": 90 }
}
```

**The 1.21.4 restructure.** As of 24w45a / 1.21.4+, item `overrides` were removed and replaced with **item model definitions** at `assets/<namespace>/items/<id>.json`, selected by the `minecraft:item_model` data component ([Items model definition](https://minecraft.wiki/w/Items_model_definition)). Minimal form:

```json
{
  "model": {
    "type": "minecraft:model",
    "model": "minecraft:item/stick"
  }
}
```

`type` can also be `minecraft:composite`, `minecraft:condition`, `minecraft:select`, `minecraft:range_dispatch`, `minecraft:empty`, or `minecraft:special`, and a `tints` array applies colour by `tintindex` from sources like `minecraft:dye` or `minecraft:potion`. The wiki also notes that from 24w45a "the game makes no distinction between block models and item models."

**The lesson:** game logic never names a texture. The chain is item id → item model definition → model → texture variable → texture path. Four hops, each independently swappable, which is why a resource pack can restyle the entire game without touching a single line of behaviour.

### 5. Enforced versus merely conventional

This split is the actual answer to "how does Minecraft standardise its art."

**Hard-enforced (pack fails to load, or the asset visibly breaks):**

- `pack.mcmeta` must exist, be at the archive root, and be valid UTF-8 JSON. No file, no pack.
- Format number outside the client's supported range marks the pack "incompatible" and it will not load. The wiki's rationale: Minecraft "prevents loading to avoid crashes from unsupported features or missing content."
- `.png` only, since 1.20.3-pre1.
- Lowercase filenames since 1.11; namespace charset `[a-z0-9-_.]`, path charset `[a-z0-9-_./]`.
- The `assets/<namespace>/<type>/` layout. Anything else fails to resolve and renders as the magenta checkerboard.
- Animated textures: image dimensions must divide evenly by frame `width`/`height`, else missing texture.
- Nine-slice sprites require `border`; `width` and `height` are required for `tile` and `nine_slice`.
- Pre-1.13 only: block and item textures had to be square.

**Degraded but not blocked (logged, quality loss, ships anyway):**

- Sprites under 16x16 or not a multiple of 2 on a mipmapped atlas limit the max mipmap level and print a log message. Nothing crashes.
- Non-square block and item textures work post-1.13 but stretch on default models.
- Missing `particle` texture logs a warning (1.21.5+).
- Nine-slice `border` ≥ 230 causes integer overflow and pulls in unrelated parts of the atlas ([gui.png-atlas](https://minecraft.wiki/w/Gui.png-atlas)). Undefined behaviour rather than a guard.

**Purely conventional, zero enforcement:**

- 16x16 base resolution.
- The 32x / 64x / 128x / 256x tier ladder.
- 128x128 `pack.png` (a "recommendation").
- Palette, outline treatment, dithering, colour count, art style, silhouette rules. Entirely unenforced.
- Vanilla-style naming inside a custom namespace.

**The pattern:** Minecraft enforces a small set of machine-checkable *structural* rules, degrades loudly rather than failing on *quality* rules, and leaves *aesthetics* to convention plus tooling. That three-tier split is what makes the ecosystem both consistent and enormous.

### 6. Distribution and validation

**Distribution.**

- **Client-side:** drop the zip into the `resourcepacks` folder. Multiple packs stack, and packs positioned higher override those below.
- **Server-side:** `resource-pack=<url>` plus `resource-pack-sha1=` in `server.properties`, with `require-resource-pack=true` to force it. The SHA1 "is meant to prevent errors due to download corruption" ([server.properties](https://minecraft.wiki/w/Server.properties)). Bedrock uses `texturepack-required`.
- **Platforms:** [Modrinth](https://modrinth.com/resourcepacks), [CurseForge](https://www.curseforge.com/minecraft/search?class=texture-packs), and Planet Minecraft. Modrinth's [Content Rules](https://modrinth.com/legal/rules) require licensing rights, no cross-platform reuploads without permission, declared dependencies, an English description, and disclosure of generative AI usage.

**Validation.** There is no official validator, but three things fill the gap:

1. **The game log itself** is the primary validator. Mipmap limitations, missing particle textures, and unresolvable references all print at load.
2. **[Mojang/slicer](https://github.com/Mojang/slicer)**, an official Mojang repo. This is the notable one: **Mojang ships a codemod for art.** When Mojang splits an atlas, the tool mechanically re-cuts existing packs. It covers 1.14 (particle, painting, mob effect textures), 1.20.2 (UI sprites), 1.20.5 (map icons), and 26.2 (bed, sign, hanging sign textures), and is run as `<input dir or zip> <output dir> [<leftover dir>]`. Its README is candid: "The migrations automated here are not exhaustive, so some manual work may still be required." The 23w31a snapshot notes credit it for splitting all GUI sheets into `textures/gui/sprites`, moving the `realms` namespace into `minecraft`, and renaming `villager2.png`.
3. **Community tooling.** [misode/mcmeta](https://github.com/misode/mcmeta) publishes a "processed, version controlled history of Minecraft's generated data and assets" from 1.14 onward, on branches including `summary`, `registries`, `data`, `assets`, `atlas`, and `diff`, which is what most pack tooling validates against. [MrKinau/ResourcePackValidator](https://github.com/MrKinau/ResourcePackValidator) is a CLI and GitHub Action whose checks (from `doc/VALIDATORS.md`) are: `AnyNamespacePresentValidator`, `ModelIsJsonObjectValidator`, `ModelParentValidator`, `ModelHasAnyTextureValidator`, `ModelTexturesExistsValidator`, `ModelTextureReferencesResolvableValidator` (including cycle detection and a 10-deep parent limit), `ModelHasParticleTextureValidator`, `ModelOverridesExistsValidator`, `UnusedFileValidator`, `TextureLimitMipLevelValidator`, `TextureIsNotCorruptedValidator`, `FontTextureExistsValidator`, `FontCharacterUsageValidator`, `InvalidPathValidator`, and `ModelRequiresOverlayOverrideValidator`.

## Part 2: Proposed Art Standard for a 16x16 Pixel Farm Game

Written so an artist can execute without asking questions. Design decisions traceable to the Minecraft findings above are marked **[MC]**.

### 2.0 Global rules (apply to every category)

**Base unit.** One tile `T` = 16 px. Every canvas size below is given for scale factor `S` = 1. A higher-resolution pack multiplies every pixel number by `S`, where `S` ∈ {1, 2, 4} only, producing 16x, 32x, 64x. **[MC]** Nothing in engine code may hardcode a pixel count; positions and sizes are expressed in tiles, the way Minecraft's UVs are expressed as 0..16 percentages, so one set of layout data serves every `S`.

**File format.** PNG-32, 8 bits per channel, RGBA, non-interlaced, no embedded ICC profile (sRGB assumed). A colour profile silently shifts palette values between Aseprite and the browser and breaks exact-match palette validation.

**Transparency.** Binary alpha only. Every pixel is alpha 0 or alpha 255, with exactly two exceptions named in §2.5 and §2.6. Additionally, every alpha-0 pixel must have RGB `0,0,0`. Stale RGB under transparent pixels causes coloured fringing at integer upscales.

**Palette.** One shared master palette, 48 swatches, at `assets/farm/palette/master.png` (a 48x1 PNG, one pixel per swatch, left to right) and `master.gpl` for Aseprite. Index 0 is reserved transparent-black. Index 1 is the universal outline neutral, the darkest value in the palette. Every shipped pixel must be an exact RGB match to a master swatch. Per-category limits below cap how many *distinct* swatches a single asset may draw from that master 48.

**Lighting.** One global rule, no per-asset deviation: key light from the upper left at 45 degrees. Top and left surfaces catch highlight, bottom and right surfaces fall into shadow. No baked drop shadows in any world asset; contact shadows are engine-drawn from shared assets.

**Reserved colour.** `#FF00FF` never appears in a shipped asset. It is the engine's missing-asset sentinel, drawn as a magenta and black checkerboard. **[MC]** Directly copied from Minecraft's missing texture (`#000000` / `#f800f8`), and for the same reason: it must be impossible to ship unnoticed.

**Naming and paths.** `[a-z0-9_]` in filenames, `/` as the only separator, all lowercase, single underscores, no spaces, no capitals. **[MC]** Minecraft mandated lowercase in 1.11 because case-insensitive macOS and Windows filesystems diverge from case-sensitive Linux CI, and that is a genuine bug class. No `_final`, `_v2`, `_new`, or `_fixed` suffixes; the filename ends with the variant or size token defined for its category and nothing else.

**Grid alignment.** Every world asset canvas is an exact multiple of 16 in both dimensions. UI is the sole exception (multiple of 8), because UI lives in a separate, non-mipmapped atlas. **[MC]** The wiki's constraint is scoped to "atlases which support mipmapping," so a non-mipmapped GUI atlas legitimately relaxes it.

**Manifest.** `assets/farm/pack.json`:

```json
{
  "pack": {
    "description": "todoFarm base art pack",
    "art_format": 1,
    "tile_size": 16,
    "scale": 1,
    "palette": "farm:palette/master"
  }
}
```

`art_format` is an opaque integer that increments on every breaking change to this document. **[MC]** It is deliberately not the game version and not a semver, exactly as `pack_format` is neither. The engine declares a supported range and refuses to load a pack outside it.

**Tick.** All timing in this spec is in ticks. One tick = 1/60 second. **[MC]** Sidecar-declared timing in an abstract tick unit, decoupled from render framerate, is Minecraft's `frametime`, retimed from 20 Hz to 60 Hz.

### 2.1 Terrain tiles

| | |
|---|---|
| **Canvas** | Single tile: **16x16**, one tile per file. Autotile set: **64x64** (a 4x4 grid of 16x16 cells). |
| **Frame layout** | Static, single frame. Animated ground (water, lava) is a Prop, §2.6, not a terrain tile. Autotile cell index = `N + 2*E + 4*S + 8*W`, where each bit is 1 when that neighbour is the *same* terrain. Cells read left to right then top to bottom, index 0 at top-left through index 15 at bottom-right. So index 0 is fully isolated, index 15 is fully surrounded. |
| **Anchor / pivot** | None. Origin is the cell's top-left pixel. The tile at grid cell `(gx, gy)` draws at `(gx*16, gy*16)`. |
| **Palette limit** | **8** distinct swatches per tile, outline included. |
| **Transparency** | Base terrain is **100% opaque**, zero alpha-0 pixels. Overlay terrain (paths, tilled soil, puddles that let ground read through) uses the `overlay_` name prefix and may use alpha 0, still binary. |
| **Naming** | `textures/terrain/<material>.png`, `textures/terrain/<material>_blob16.png`, `textures/terrain/overlay_<material>.png`. Examples: `soil.png`, `grass_blob16.png`, `overlay_tilled.png`. |

**Seam rule.** Every terrain tile must tile seamlessly against itself: the rightmost column must be continuous with the leftmost, and the bottom row with the top. Test by laying the tile out 3x3 and looking for a visible grid.

### 2.2 Characters with 4-direction walk cycles

| | |
|---|---|
| **Canvas per frame** | **16x32** (one tile wide, two tiles tall). The character occupies one tile of floor and reads one tile above it. |
| **Sheet layout** | One PNG per character per state. **Rows are directions, always 4, in this fixed order top to bottom: 0 south (toward camera), 1 west, 2 east, 3 north.** Columns are frames, left to right, looping. `idle` and `use` are 4 columns (**64x128**). `walk` and `carry` are 8 columns (**128x128**). |
| **Walk frame order** | Column 0 contact-left, 1 down-left, 2 pass-left, 3 up-left, 4 contact-right, 5 down-right, 6 pass-right, 7 up-right. |
| **Anchor / pivot** | The **feet anchor is pixel (8, 31)** in every frame: horizontal centre of the 16 px width, last row of the 32 px canvas. That pixel is placed at the character's world position. The supporting foot's contact point sits on row 31. **The anchor never moves between frames.** Vertical bob is drawn *into* the frame; the canvas origin stays fixed. This single rule eliminates an entire class of jitter bugs. |
| **Palette limit** | **12** distinct swatches per character, outline included. Budget: 3 skin, 2 hair, two 3-value clothing ramps, 1 outline, 1 accent. |
| **Transparency** | Binary alpha. No ground shadow drawn into the sheet. The shadow is a shared engine-drawn asset, `textures/character/shadow.png`, 16x16, placed beneath the anchor. |
| **Outline** | Required. 1 px, master palette index 1, on the full silhouette. Consistent outlining is what makes a cast read as one game. |
| **Mirroring** | **Forbidden at runtime.** East and west are authored separately. Mirroring breaks any asymmetric character (a tool in the right hand). |
| **Naming** | `textures/character/<name>_<state>.png` plus a required sidecar `<name>_<state>.png.json`. States: `idle`, `walk`, `use`, `carry`. Examples: `farmer_walk.png`, `farmer_walk.png.json`, `goat_idle.png`. |

**Required sidecar** (`farmer_walk.png.json`):

```json
{
  "animation": {
    "frame_width": 16,
    "frame_height": 32,
    "columns": 8,
    "rows": 4,
    "row_order": ["south", "west", "east", "north"],
    "frametime": 6,
    "interpolate": false,
    "loop": true
  }
}
```

`frametime: 6` at 60 ticks per second is 100 ms per frame, an 800 ms walk cycle. **[MC]** Sidecar naming (`<texture>.png.json`) and the `frametime` / `interpolate` field semantics are lifted from Minecraft's `.png.mcmeta`.

### 2.3 Furniture and decorations, 1x1 and 2x2

| | |
|---|---|
| **Canvas** | `canvas = (footprint_w * 16) x (footprint_h * 16 + 16)`. So **1x1 → 16x32**, **2x2 → 32x48**. Every object gets exactly one tile of riser height above its footprint. A flat object (a rug) simply leaves the top 16 rows transparent. |
| **Frame layout** | Static, single frame. State variants (chest open/closed, lamp lit/unlit) are **separate files**, never frames. Anything that moves on its own is a Prop, §2.6. |
| **Anchor / pivot** | **Bottom-left pixel of the footprint, `(0, H-1)`** where `H` is canvas height. The footprint rectangle is the bottom `footprint_h * 16` rows. The engine places `(0, H-1)` at the bottom-left corner of the object's origin tile. Practically: draw the object's floor contact within the bottom 16 rows (1x1) or bottom 32 rows (2x2); anything above that overhangs into the tile behind. |
| **Overhang limit** | An object may not extend more than **4 px** horizontally past its footprint on either side. Depth sorting uses the footprint's bottom edge, and wider overhangs make occlusion read wrong. |
| **Palette limit** | **10** distinct swatches per object. |
| **Transparency** | Binary alpha, alpha-0 pixels RGB `0,0,0`. No baked contact shadow. Engine draws `textures/furniture/shadow_1x1.png` and `shadow_2x2.png`. |
| **Naming** | `textures/furniture/<name>[_<state>]_<w>x<h>.png` for collidable objects, `textures/decoration/<name>[_<state>]_<w>x<h>.png` for non-collidable, identical rules. Examples: `furniture/stool_1x1.png`, `furniture/chest_closed_1x1.png`, `furniture/chest_open_1x1.png`, `furniture/bed_2x2.png`, `decoration/rug_2x2.png`. |

### 2.4 Item icons

| | |
|---|---|
| **Canvas** | **16x16**, always. There are no multi-tile items. |
| **Frame layout** | Static, single frame. No animated icons in `art_format` 1. |
| **Anchor / pivot** | None; the icon fills its slot. **Composition rule instead: all artwork fits inside the central 14x14 region, leaving a 1 px empty margin on all four sides.** The margin guarantees the icon never touches its slot border and never bleeds into neighbours in the atlas. |
| **Palette limit** | **8** distinct swatches per icon. |
| **Transparency** | Binary alpha, background alpha 0 / RGB `0,0,0`. A **1 px outline in master palette index 1 on the full silhouette is required**, unlike terrain, because icons sit on varying UI backgrounds. |
| **Orientation** | Items are drawn at a 3/4 tilt with the long axis running bottom-left to top-right, consistent with the global upper-left key light. Tools: handle down-left, business end up-right. This settles "which way does the hoe face" permanently. |
| **Naming** | `textures/item/<name>.png`. Tier variants use a closed suffix set: `_common`, `_silver`, `_gold`, `_iridium`. Stack counts and durability bars are engine-drawn overlays, never baked into the icon. |

**Required index.** Every icon must have an entry in `textures/item/_index.json`. Nothing renders without one:

```json
{
  "farm:parsnip": { "texture": "farm:item/parsnip" },
  "farm:hoe":     { "texture": "farm:item/hoe_common" }
}
```

**[MC]** This is our analogue of Minecraft's item model definition layer (`assets/<ns>/items/<id>.json`). Game logic names an item id, never a file path, so renaming or restyling an asset never touches code.

### 2.5 UI nine-slice frames

Modelled directly on Minecraft's GUI sprite scaling so that tooling written against either format works for both.

| | |
|---|---|
| **Atlas** | UI lives in a **separate, non-mipmapped atlas**. Dimensions are therefore multiples of **8**, not 16. |
| **Canvas** | The source sprite is the minimum drawable unit: `2*B + C` px on each axis, where `B` is border width and `C` is centre width. Three standard sizes, pick one: **`sm`: B=4, C=8 → 16x16**. **`md`: B=8, C=8 → 24x24**. **`lg`: B=12, C=8 → 32x32**. Border is uniform on all four sides unless the sidecar declares per-side values. |
| **Frame layout** | Static. The nine regions are *implied* by `B`, never drawn as separate cells: four `BxB` corners, four `BxC` / `CxB` edges, one `CxC` centre. |
| **Anchor / pivot** | None. Nine-slice sprites are stretched to a target rect. **The rule the artist follows instead: the `CxC` centre must tile seamlessly with itself in both axes, and each edge strip must tile seamlessly along its long axis**, because centre and edges are tiled rather than stretched unless `stretch_inner` is true. |
| **Palette limit** | **6** distinct swatches per frame. UI must not compete with world art. |
| **Transparency** | **Exception 1 of 2.** The outermost 1 px ring may use a single fixed alpha of **96** in master palette index 1, for the drop shadow. Every other pixel is alpha 0 or 255. A soft UI shadow survives integer upscaling; a soft world sprite does not. |
| **Naming** | `textures/ui/<component>_<size>[_<state>].png` plus a required sidecar. Size ∈ {`sm`, `md`, `lg`}. State suffix last, from {`hover`, `pressed`, `disabled`}. Examples: `ui/panel_md.png`, `ui/button_sm.png`, `ui/button_sm_hover.png`, `ui/tooltip_sm.png`. |

**Required sidecar** (`ui/panel_md.png.json`), field names and semantics identical to Minecraft's:

```json
{
  "gui": {
    "scaling": {
      "type": "nine_slice",
      "width": 24,
      "height": 24,
      "border": 8,
      "stretch_inner": false
    }
  }
}
```

`type` ∈ {`stretch`, `tile`, `nine_slice`}. `width` and `height` are required for `tile` and `nine_slice` and must equal the PNG's real dimensions. `border` may instead be an object: `{"left": 8, "top": 12, "right": 8, "bottom": 8}`. **[MC]** Wiki definitions: `nine_slice` means "the sprite is sliced into 4 corners, 4 edges, and 1 center slice, which is tiled across the desired space"; `tile` means "the sprite is repeated across the desired space, starting from the top-left"; `stretch_inner` "if true, the inner parts of the texture is stretched instead of tiled."

**Guard we add that Minecraft lacks.** Minecraft's `border` ≥ 230 causes silent integer overflow and pulls unrelated atlas regions into the frame. Our validator hard-fails on `border >= 128` and on `2*border >= min(width, height)`.

### 2.6 Animated props

| | |
|---|---|
| **Canvas per frame** | Same footprint formula as furniture: `(footprint_w * 16) x (footprint_h * 16 + 16)`. **1x1 → 16x32 per frame. 2x2 → 32x48 per frame.** |
| **Frame layout** | **Vertical strip.** Frame 0 at the top, frame `n` directly below frame `n-1`, no gaps, no padding, no margins. Sheet width = frame width. Sheet height = `frame_height * frame_count`. **[MC]** Minecraft's default. Chosen deliberately: a strip makes the frame size inferable and is trivial to eyeball in code review. |
| **Frame count** | Any positive integer. No power-of-two requirement on frame count. But **sheet height must divide evenly by `frame_height`** or the asset fails validation. **[MC]** Directly mirrors the wiki's rule that "the total dimensions of the image must be divisible by the `width` and `height`" or the missing texture displays. |
| **Anchor / pivot** | Identical to furniture: **bottom-left pixel of the footprint, `(0, H-1)` of each frame. The anchor never moves between frames.** All motion is drawn inside the frame. |
| **Palette limit** | **10** distinct swatches across the **entire strip**, not per frame. A per-frame limit lets the palette drift and the prop shimmers. |
| **Transparency** | Binary alpha in the base strip, zero partial alpha. **Exception 2 of 2:** an emissive prop ships a second strip `<name>_glow.png` with identical dimensions and frame count, containing only the emissive pixels. The glow strip is additively blended by the engine and may use partial alpha. |
| **Naming** | `textures/prop/<name>_<w>x<h>.png`, required sidecar `<name>_<w>x<h>.png.json`, optional `<name>_<w>x<h>_glow.png`. Examples: `prop/waterwheel_2x2.png`, `prop/campfire_1x1.png`, `prop/campfire_1x1_glow.png`. |

**Required sidecar** (`prop/campfire_1x1.png.json`):

```json
{
  "animation": {
    "frame_width": 16,
    "frame_height": 32,
    "frametime": 8,
    "interpolate": false,
    "loop": true,
    "frames": [0, 1, 2, {"index": 3, "time": 20}, 2, 1]
  }
}
```

- `frametime`: default duration of one frame in ticks (1/60 s). Defaults to 1.
- `frames`: optional. Omitted means play `0..n-1` in order. Entries are an integer index or `{"index": i, "time": t}` where `time` overrides `frametime` for that entry. The example ping-pongs and holds frame 3 for 20 ticks. **[MC]** This is Minecraft's per-frame `time` override, and it exists so an artist holds a pose without drawing duplicate frames.
- `interpolate`: cross-fade when `frametime > 1`. Defaults to false. Keep false for pixel art; allowed true only on liquid and glow strips.
- `loop`: false plays once and holds the final frame.

### 2.7 Validation, and the enforced-versus-conventional split

**[MC]** Minecraft's three-tier split is the model, with one deliberate departure noted below.

**Hard fail, CI blocks the commit:**

1. Filename or path contains anything outside `[a-z0-9_/.]`, or any uppercase character.
2. Not PNG-32, or interlaced, or carries an ICC profile.
3. Canvas dimensions do not match the category's size formula.
4. Any pixel whose RGB is not an exact match to a master palette swatch.
5. Distinct-swatch count exceeds the category limit.
6. Any partial alpha outside the two declared exceptions (UI 1 px shadow ring at alpha 96, prop `_glow` strips).
7. Any alpha-0 pixel with non-zero RGB.
8. `#FF00FF` appears anywhere.
9. Animated strip height not divisible by the declared `frame_height`.
10. Missing required sidecar for a prop, a character state, or a nine-slice UI frame.
11. Sidecar `width` / `height` not equal to the PNG's real dimensions.
12. Nine-slice sidecar missing `border`, or `border >= 128`, or `2*border >= min(width, height)`.
13. An item PNG with no entry in `item/_index.json`, or an index entry pointing at a missing file.
14. Character float check: in every frame of every character sheet, the opaque bounding box's bottom edge must fall within rows `H-3` to `H-1`.

**Warn only, does not block:**

15. Terrain tile does not seam-test clean at 3x3.
16. Item artwork touches the outer 1 px margin.
17. Asset file referenced by nothing.
18. Distinct-swatch count under 3 (likely unfinished).
19. Character `walk` sheet with a column count other than 8.

**Deliberate departure from Minecraft.** Minecraft *degrades* on off-size textures (mipmap level drops, a log line prints, the pack ships anyway). We **hard-fail** on canvas size and palette instead. Justification: Minecraft's leniency exists to serve tens of thousands of independent pack authors it cannot coordinate with. We are one team with one atlas, and a hard fail is cheaper than a log line nobody reads.

**Tooling to build, in Minecraft's shape:**

- Bump `art_format` on every breaking change to this document; CI asserts the engine's supported range covers the pack's declared value.
- Keep the master palette and this spec version-controlled so an artist can diff exactly what changed between `art_format` 1 and 2. **[MC]** This is what misode/mcmeta does for vanilla assets, and it is why pack authors can survive Mojang's format churn.
- Ship a migration script with every `art_format` bump that mechanically re-cuts existing assets. **[MC]** Mojang/slicer. Set expectations the way Mojang's own README does: "some manual work may still be required."

---

### What I would explicitly *not* copy from Minecraft

- **Tolerance for off-size textures.** See above.
- **20 ticks per second.** Use 60.
- **The block model / item model 3D layer.** We are 2D. That entire indirection collapses into `item/_index.json`.
- **Undefined behaviour on out-of-range values.** The `border >= 230` overflow is a bug Minecraft documents rather than fixes. We guard it.
